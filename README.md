# YADRO: свёртка трёх матриц на C17

Решение тестового задания на чистом C. Программа читает три матрицы A, B, C
и общее ядро D из бинарного файла, вычисляет результат для каждой матрицы
и записывает его в другой бинарный файл.

Для отправки на проверку нужен только **`solution.c`**. Решение использует
стандартную библиотеку C; сторонние библиотеки и C++ не требуются.
`CMakeLists.txt` предназначен для локальной разработки, в том числе в CLion.

## Задание

Матрицы A, B и C имеют одинаковые размеры H × W. Ядро D имеет нечётные
размеры DH × DW и содержит знаковые коэффициенты. Для каждого канала
вычисляется сумма:

```text
S(y, x, c) = Σ D(ky, kx) · X(y + ky − DH/2, x + kx − DW/2, c)
```

Здесь `c` обозначает A, B или C, `ky` и `kx` перебирают все элементы ядра,
а деление размеров на 2 — целочисленное. Элементы X за границами матрицы
считаются нулевыми. Ядро **не переворачивается**: используется именно
расположение коэффициентов, показанное в формуле задания.

После накопления полной суммы выполняется преобразование:

| Значение суммы S | Выходной байт |
|---|---|
| `S > 255` | `S % 251` |
| `S < 0` | `(-S) % 241` |
| `0 ≤ S ≤ 255` | S без изменений |

Например, 255 остаётся 255, 256 превращается в 5, а −242 — в 1.
Операции modulo не применяются к промежуточным суммам.

## Формат файлов

Все матрицы хранятся построчно. Элементы A/B/C чередуются:
`A1, B1, C1, A2, B2, C2, …`. Обозначим `N = H * W`.

### Вход

| Смещение, байт | Содержимое | Размер | Тип C |
|---|---|---|---|
| 0 | H — высота матриц | 4 байта | `uint32_t` |
| 4 | W — ширина матриц | 4 байта | `uint32_t` |
| 8 | Чередующиеся элементы A/B/C | `3*N` байт | `uint8_t` |
| `8 + 3*N` | DH — высота ядра | 2 байта | `uint16_t` |
| `10 + 3*N` | DW — ширина ядра | 2 байта | `uint16_t` |
| `12 + 3*N` | Коэффициенты D | `DH*DW` байт | `int8_t` |

### Выход

| Смещение, байт | Содержимое | Размер |
|---|---|---|
| 0 | Исходное H | 4 байта |
| 4 | Исходное W | 4 байта |
| 8 | Чередующиеся элементы A′/B′/C′ | `3*N` байт |

Размер результата — ровно `8 + 3*N` байт. Ядро в выходной файл не записывается.

Многобайтовые поля используют **native endianness**, то есть порядок байтов
системы, как требует ТЗ. Программа не преобразует их в little-endian.
Предоставленные бинарные примеры и тестовые файлы используют little-endian;
перенос этих файлов на систему с другим порядком байтов потребует преобразования.

## Сборка и запуск

### GCC

```sh
gcc -std=c17 -O2 -Wall -Wextra -Wpedantic solution.c -o solution
```

На macOS с Homebrew GCC вместо `gcc` можно использовать `gcc-16`.
Системная команда `gcc` на macOS может запускать Apple Clang — версию
компилятора можно проверить через `gcc --version`.

```sh
./solution -i open-tests/exmaple.in -o result.bin
cmp result.bin open-tests/exmaple.out
```

Имя `exmaple` соответствует имени файла в исходном открытом наборе.
Порядок флагов свободный:

```sh
./solution -o result.bin -i open-tests/exmaple.in
```

Если имя входного или выходного файла не задано, программа возвращает `10`.
Следующий известный флаг не считается именем файла:

```sh
./solution -i -o result.bin
# Код возврата: 10
```

Имена с начальным `-` допустимы, если они не равны `-i` или `-o`.
Успешное завершение возвращает `0`; ошибки чтения, памяти или записи —
`EXIT_FAILURE` (в проверяемом окружении — `1`). Диагностика выводится в stderr.

### CMake / CLion

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/solution -i open-tests/exmaple.in -o result.bin
```

### Санитайзеры

```sh
gcc-16 -std=c17 -O1 -g -Wall -Wextra -Wpedantic \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  solution.c -o solution-debug
```

Если установленный GCC не поддерживает или не может слинковать санитайзеры,
на macOS ту же команду можно выполнить через `clang` вместо `gcc-16`.
Release-сборка и замеры производительности выполняются через GNU GCC.

### Если Homebrew GCC не находит заголовки macOS SDK

В локальном окружении GCC 16.2.0 был настроен на отсутствующий SDK macOS 26,
а установлен SDK 14.2. Для этой конфигурации рабочая команда сборки:

```sh
gcc-16 \
  -isysroot /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
  -isystem /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include \
  -std=c17 -O2 -Wall -Wextra -Wpedantic solution.c -o solution
```

Путь к установленному SDK показывает `xcrun --show-sdk-path`. Эти два
параметра также применялись при локальной sanitizer-сборке; менять
`solution.c` для обхода проблемы SDK не требуется.

## Тестирование

### 12 открытых тестов

Каждый тест — пара `.in` / `.out`. Результат сравнивается с эталоном
побайтово, включая заголовок и длину файла.

Оригинальный скрипт рассчитан на Linux и использует `timeout`:

```sh
bash open-tests/run-tests.sh ./solution
```

Для macOS без `timeout` можно запустить те же пары через Python 3 и `cmp`.
Ни тестовые данные, ни исходный скрипт изменять не нужно:

```sh
python3 - <<'PY'
from pathlib import Path
import subprocess
import tempfile
import time

program = Path("solution").resolve()
inputs = sorted(Path("open-tests").glob("*.in"))
if not inputs:
    raise SystemExit("Тестовые файлы не найдены")

with tempfile.TemporaryDirectory() as directory:
    actual = Path(directory) / "actual.out"
    for source in inputs:
        started = time.perf_counter()
        subprocess.run(
            [str(program), "-i", str(source), "-o", str(actual)],
            check=True, timeout=60,
        )
        elapsed = time.perf_counter() - started
        subprocess.run(
            ["cmp", str(actual), str(source.with_suffix(".out"))],
            check=True,
        )
        print(f"PASS {source.stem}: {elapsed:.3f} с")

print(f"Passed {len(inputs)}/{len(inputs)} tests")
PY
```

### 120 дополнительных тестов

```sh
python3 yadro_120_tests/run_120_tests.py ./solution
```

Набор содержит 98 корректных бинарных примеров, 14 проверок некорректного
ввода и 8 проверок аргументов и путей. Подробности — в
[описании набора](yadro_120_tests/README.md).

Проверяются знаковость коэффициентов, отсутствие переворота ядра, границы,
ядра больше матрицы, пороги преобразования суммы, случайные примеры,
нулевые размеры, усечённые файлы и аргументы командной строки.
Проверки некорректного ввода и нулевых размеров матриц дополняют ТЗ,
а не вводят новые требования к его гарантированно корректным входам.

## Устройство решения

`parse_arguments` разбирает имена файлов, `read_input` читает формат,
`convolve` вычисляет три результата, `normalize_sum` преобразует суммы,
а `write_output` записывает файл. `main` управляет вызовами и освобождает память.

Индекс канала `c` в позиции `(y, x)` — `3*(y*W + x) + c`, где A/B/C
соответствуют `c = 0/1/2`. Индекс коэффициента ядра — `ky*DW + kx`.

Допустимые диапазоны ядра вычисляются до внутреннего цикла. Три суммы
накапливаются одновременно; за границами матрицы вычисления не выполняются.
Входной и выходной буферы раздельные. Выделения памяти внутри циклов нет.

Суммы и произведения вычисляются в `int64_t`. Даже предельная оценка
`65535² * 255 * 128 = 140183454384000` помещается в этот тип.
Для размеров и индексов используется `size_t`; перед выделением памяти
проверяется переполнение размеров.

Проверяются результаты `fopen`, `fread`, `malloc`, `fwrite` и `fclose`.
Ошибка закрытия выходного файла считается ошибкой записи, поскольку данные
могут оставаться в буфере stdio. Открытые файлы закрываются, память освобождается
и при успешном завершении, и при ошибках.

При H = 0 или W = 0 программа не выделяет пустые буферы A/B/C и результата,
но всё равно читает DH, DW и D. После успешного чтения выход содержит только
8-байтовый заголовок. Ядро с нулевой или чётной стороной отклоняется.

## Сложность и результаты проверки

Прямая свёртка имеет сложность `O(H * W * DH * DW)` по времени.
Основные буферы занимают `6*H*W + DH*DW` байт: вход, результат и ядро.
Отсечение границ уменьшает фактическое число операций, но не меняет эту оценку.

При локальной проверке 14 октября 2026 года release-сборка прошла **12/12
открытых и 120/120 дополнительных тестов**. Сборка выполнена без предупреждений.

Решение ранее прошло все 12 открытых тестов и под ASan/UBSan через GNU GCC
16.2.0. LeakSanitizer в этом окружении отключался (`detect_leaks=0`) из-за
зависания; ASan и UBSan оставались включены. Освобождение ресурсов дополнительно
проверялось принудительными отказами выделения памяти и закрытия файлов.

Замеры release-сборки GNU GCC 16.2.0 с `-O2` от 14 октября 2026 года:

| Тест | H × W | DH × DW | Полное время процесса |
|---|---|---|---|
| large1 | 529 × 770 | 41 × 51 | 0,346 с |
| large2 | 1020 × 967 | 65 × 81 | 1,580 с |
| large3 | 635 × 464 | 63 × 47 | 0,443 с |

Лимит открытого скрипта — 60 секунд на тест. Эти измерения относятся к
локальной машине; на другом оборудовании время будет отличаться.
Прохождение открытых тестов не гарантирует прохождение закрытого набора.
